# PLC_price_OPTA — управление реле по цене электроэнергии

Прошивка для **Arduino Opta WiFi**. Устройство включает и выключает нагрузки
на 4 реле в зависимости от биржевой цены
электроэнергии **Nord Pool, зона Латвия (LV)**. Цены берутся из открытого API
[Elering](https://dashboard.elering.ee).

Сейчас устройство управляет бойлером, но задумано как универсальный контроллер
нагрузок для умного дома (освещение, насосы, вентиляция и т.д.). Поэтому в коде и
документации реле — это «нагрузка» или «канал», а не «нагрев» (D-010).

## Возможности

- 4 независимых реле (D0–D3), у каждого свои настройки.
- Новая цена каждые 15 минут, цены вчера–сегодня–завтра по 15-минутным интервалам.
- Сценарии для каждого реле (подробно — [docs/SCENARIOS.md](docs/SCENARIOS.md)):
  - **аварийный предел** — выше этой цены реле всегда выключено;
  - **порог включения** — ниже этой цены реле всегда включено;
  - **умный порог** — N часов самых дешевых 15-минутных интервалов за сутки;
  - **включение перед пробуждением** — ровно N часов до заданного времени;
  - **включение ночью** — N часов самых дешевых интервалов ночного окна, ближе к утру
    при разнице до 1 цента;
  - **отпуск** — реле выключено до возвращения, кроме N часов дешевых интервалов
    в последние 10 часов перед ним;
  - **принудительное включение** — кнопка на веб-странице включает реле на заданное
    время, не глядя на цену (экстренное включение по сети), с кнопкой «Остановить»
    и оставшимся временем на странице.
- Веб-страница настроек с графиком цены и плана работы (вчера, сегодня, завтра)
  и историей переключений с причинами: `http://opta-settings.local`.
- Работа по Wi-Fi. Ethernet служит для доступа к странице настроек.
- Точка доступа `Opta-Config-AP` для первой настройки Wi-Fi.
- Ручное управление: кнопка USER на корпусе и команды в Serial-мониторе.
- Защита: если новой цены нет больше часа, автоматические реле выключаются.
  Аппаратный watchdog перезагружает зависшее устройство.

## Быстрый старт

1. Установить [VS Code](https://code.visualstudio.com) и расширение **PlatformIO IDE**.
2. Открыть папку проекта, подключить Opta по USB-C.
3. Собрать и прошить: `pio run -e opta -t upload`.
4. Открыть монитор порта: `pio device monitor -b 115200`.
5. При первом запуске Opta поднимает Wi-Fi-сеть **Opta-Config-AP** (пароль `opta1234`).
   Подключиться к ней, открыть `http://192.168.4.1`, ввести SSID и пароль домашней сети,
   нажать «Сохранить настройки». Устройство перезагрузится и подключится к сети.
6. Дальше страница настроек доступна по адресу `http://opta-settings.local`
   или по IP-адресу из Serial-монитора.

Подробности, кнопка, светодиоды и диагностика — [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Структура репозитория

```
src/main.cpp        сеть, веб, консоль, расписание (идет рефакторинг монолита)
src/platform/       железо: лог, KVStore, выходы реле, кнопка USER, светодиод
lib/                чистое ядро без Arduino: время, цены, настройки и их хранение,
                    планировщик, разбор API Elering, формы, DNS, история
                    переключений, кнопка
                    (docs/ARCHITECTURE.md §2–3)
test/               unit-тесты lib/ на ПК: pio test -e native
docs/               документация (см. ниже)
platformio.ini      конфигурация сборки (opta — прошивка, native — тесты)
CLAUDE.md           инструкции для ИИ-агентов
```

## Статус

- Этап 1 — критические исправления безопасности (ветка `fix/critical-bugs`), ожидает
  проверки на устройстве.
- Этап 2 — разбиение `main.cpp` на модули с unit-тестами, исправление планировщика,
  новое «принудительное включение». План — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#6-порядок-переноса-этап-2).
  Шаг 2a (чистое ядро `lib/` и тесты) выполнен в ветке `refactor/core-l0`, шаг 2b
  (исправленный планировщик по 15-минутным интервалам, история переключений) — в ветке
  `fix/planner`, шаг 2c (принудительное включение вместо «непрерывного блока») — в ветке
  `feature/force-on`, шаг 2d (хранение настроек, выходы, кнопка и светодиод — в
  отдельные модули) — в ветке `refactor/config-price-relay`; все ожидают проверки на
  устройстве.
