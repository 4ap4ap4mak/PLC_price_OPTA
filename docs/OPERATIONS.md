# Эксплуатация и диагностика

Как пользоваться устройством, что означают индикаторы и что делать, если что-то
не работает. Логика решений реле описана в [SCENARIOS.md](SCENARIOS.md).

## 1. Подключение

| Вывод Opta | Назначение |
|---|---|
| Реле 1–4 (D0–D3) | нагрузки; у каждого реле свой зеленый светодиод состояния |
| USB-C | питание при отладке, прошивка, Serial-монитор 115200 бод |
| RJ45 Ethernet | необязательно: интернет и страница настроек по проводу (D-036) |
| Кнопка USER | ручное управление реле 1 и вход в режим настройки Wi-Fi |
| Светодиод LED_USER | состояние сети |

Интернет нужен для получения цен и времени. Он берется через **Wi-Fi**, если тот
подключен к сохраненной сети, иначе через **Ethernet** (D-036): вне зоны Wi-Fi устройство
по кабелю работает так же, как по Wi-Fi. Канал виден в логе:
`[HTTP] Подключение к dashboard.elering.ee через Ethernet...`. Через Ethernet проверено
только на сборке, на железе — нет (нет кабеля).

## 2. Последовательность запуска

0. Запуск аппаратного watchdog (D-041): если запуск оборвется фатальной ошибкой
   (мигание красным), через ~33 с устройство перезагрузится само.
   Если ядро не прочитало данные платы из QSPI (плата видна как VID 0xFFFF — сброс
   пришелся на стирание или запись QSPI), пауза 1,5 с и одна перезагрузка (KI-032).
1. Загрузка настроек реле из flash. Если их нет или они повреждены, записываются
   настройки по умолчанию. Если они есть, но не читаются (3 попытки), реле работают на
   настройках по умолчанию, а запись во flash заблокирована до перезапуска, чтобы не
   затереть сохраненные: страница показывает предупреждение, «Сохранить» отвечает
   ошибкой 503; снять блокировку — перезапуск или `config reset` (D-037).
2. Все реле **выключены**.
3. Ethernet: запуск DHCP без ожидания. Когда адрес получен (обычно за 1–3 с),
   запускается HTTP-сервер — один на все интерфейсы (D-033): `[WEB] HTTP-сервер слушает
   порт 80 на всех интерфейсах.`, затем `[WEB] Настройки по Ethernet: http://…`.
4. Строка `[WATCHDOG] … таймаут N мс`. `setup()` закончен, дальше все идет в `loop()`: кнопка,
   консоль и страница по Ethernet работают, пока Wi-Fi подключается (D-029).
5. Wi-Fi: через 3 с (или раньше, как только Ethernet получил адрес) — подключение
   к сохраненной сети в фоновом потоке. Попытка обычно занимает несколько секунд.
   - Неудача → до 5 попыток с паузами 5, 15, 30, 60 с (строки
     `[WiFi] Попытка N из 5 не удалась (… мс); следующая через … с.`). Сразу после
     прошивки первая попытка обычно не удается, подключается вторая (KI-001).
   - Успех → запросы времени NTP и цены ставятся в фоновый поток → отчет о статусе
     (цены в нем еще нет, таймер: «Идет запрос цены»). Решение для реле — когда придут
     время, цена и прогноз, обычно через несколько секунд.
     Страница доступна по адресу Wi-Fi (`[WEB] Настройки по Wi-Fi: http://…`) и, если
     есть, по адресу Ethernet: сервер один на оба интерфейса (D-033).
     `opta-settings.local` отвечает адресом Ethernet, если он есть, иначе адресом Wi-Fi
     (`[mDNS] opta-settings.local отвечает адресом …`). Когда кабель и Wi-Fi от одного
     роутера, имя работает со всех устройств; если сети разные — из сети Wi-Fi
     страница открывается по IP.
   - Есть Ethernet с адресом → время и цена запрашиваются по Ethernet, не дожидаясь
     Wi-Fi (D-036).
   - Все 5 попыток не удались (около 2–3 минут) и есть Ethernet → поля Wi-Fi
     показываются на странице по Ethernet (необязательные: пустые — сеть не меняется),
     попытки продолжаются раз в 10 с, цены идут по Ethernet.
   - Все 5 попыток не удались и нет Ethernet → запуск точки настройки `Opta-Config-AP`
     (§5). Не ждать: удержание USER 5 секунд открывает ее сразу.
   - Сохраненной сети нет → сразу точка настройки или поля Wi-Fi по Ethernet.
6. Потоки сетевых запросов и подключения Wi-Fi запускаются перед сетью. Если поток
   запросов не запустился — `[ERROR] Не удалось запустить поток сетевых запросов…`,
   цены и время не запрашиваются, через час реле выключит failsafe. Если не запустился
   поток подключения — `[ERROR] Не удалось запустить поток подключения Wi-Fi…`:
   подключение работает, но останавливает `loop()`, как до D-029.

## 3. Индикация

| Индикатор | Состояние | Значение |
|---|---|---|
| LED_USER | медленное мигание (1,5 с) | есть связь: Wi-Fi подключен или у Ethernet есть адрес (D-036) |
| LED_USER | быстрое мигание (0,2 с) | нет связи: ни Wi-Fi, ни Ethernet (поиск сети или точка настройки) |
| LED D0–D3 | горит | соответствующее реле включено |

## 4. Кнопка USER

| Действие | Результат |
|---|---|
| Короткое нажатие | переключить реле 1 в ручном режиме — рычаг: держится, пока реле не вернут автоматике на странице или командой `auto 1` (D-034); отменяет принудительное включение реле 1 |
| Удержание 5 секунд | режим настройки Wi-Fi: точка доступа `Opta-Config-AP`, а если работает Ethernet — поля Wi-Fi на странице по Ethernet. Если в этот момент идет попытка подключения, точка запускается сразу после нее (`[WiFi] Точка настройки запустится после текущей попытки подключения.`) |

Удержание 5 секунд **не** переключает реле.

## 5. Настройка Wi-Fi (точка доступа)

- Сеть: **Opta-Config-AP**, пароль **opta1234**.
- Страница: `http://192.168.4.1`. Captive-DNS отвечает адресом 192.168.4.1 на любое имя,
  поэтому телефон обычно сам открывает страницу.
- На странице появляются поля «Имя сети (SSID)» и «Пароль Wi-Fi». После «Сохранить
  настройки» устройство **без перезагрузки** подключается к новой сети (D-031): страница
  «Сеть Wi-Fi сохранена», через 1,5 с точка закрывается, в логе
  `[WiFi] Сохранена новая сеть; подключение без перезагрузки...`. Реле, принудительное
  включение и история сохраняются. Подключите телефон к домашней сети и откройте
  `http://opta-settings.local`.
- Не подключилось (3 попытки с паузами 5 и 15 с, около минуты) → `[WiFi] К новой сети
  подключиться не удалось; проверьте имя и пароль.` и снова точка настройки (или поля
  Wi-Fi по Ethernet).
- «Сохранить и перезапустить» с новой сетью — как раньше: запись и перезагрузка.
- Пока работает точка доступа, устройство **каждые 5 минут** пробует вернуться
  к сохраненной сети (на случай временного сбоя роутера). Если страницу открывали
  в последние 2 минуты, попытка откладывается, чтобы не прерывать ввод.
- Failsafe работает и в этом режиме: без цены больше часа автоматические реле выключатся.

## 6. Потеря Wi-Fi в работе

- Повторное подключение: первая попытка сразу, затем раз в 10 секунд после неудачной.
  Попытка идет в фоновом потоке, страница по Ethernet, консоль и кнопка работают.
- После 3 неудачных попыток при отсутствии адреса Ethernet запускается точка настройки
  (дальше — §5).
- Попытка подключения дольше 3 минут считается зависшей: `[ERROR] Подключение к Wi-Fi не
  завершилось за 180 с; перезагрузка устройства.` Во время принудительного включения
  перезагрузка откладывается до его конца (как для сетевых запросов, D-026).
- Если у Ethernet есть адрес, цены идут по нему, пока Wi-Fi нет (D-036).
- Пока связи нет, реле работают по плану из загруженного прогноза, но не дольше 1 часа без новой цены (failsafe, D-035).

## 7. Веб-страница настроек

Адреса: `http://opta-settings.local` (mDNS), IP из Serial-монитора, `http://192.168.4.1`
в режиме точки доступа.

**Подключен Home Assistant** (D-042): вверху плашка «Смотрите Home Assistant», поля
и кнопки настроек, ручного режима, принудительного включения и прошивки серые
и не нажимаются; выбор реле, вкладки графика и история работают. Изменения — в Home
Assistant, кнопка USER работает как обычно. Как только связь с брокером пропадает,
следующая загрузка страницы снова полная. Отправка формы, открытой до подключения,
отклоняется страницей «Смотрите Home Assistant» (`[WEB] Запрос POST … отклонен` в логе).
Формы отправляются с `autocomplete='off'`: иначе Firefox при обновлении страницы
восстанавливал кнопки серыми, хотя Home Assistant уже отключен.

**Панель «Home Assistant (MQTT)»** (D-042, только в прошивке с MQTT): адрес брокера,
порт, пользователь и пароль. «Сохранить и подключиться» записывает их во flash
(`/kv/mqtt`) и подключается сразу, без перезагрузки; пустой пароль — оставить
сохраненный (на страницу он не выводится). «Выключить MQTT» стирает адрес. Пока Home
Assistant подключен, панель тоже серая: сменить брокер — удержание USER 5 секунд (точка
настройки, там MQTT не подключен) или команда `mqtt`.

1. Выберите реле в списке «Настраиваемое реле» — страница перезагрузится с его
   настройками (адрес `/?relay=N`). Выбор хранится в адресе страницы, а не в
   устройстве: в двух вкладках можно держать разные реле, а адрес без `relay`
   открывает реле 1. После «Сохранить» и кнопок принудительного включения страница
   возвращается к тому же реле.
2. Панель «Ручной режим»: «Включить вручную» и «Выключить вручную» ставят реле в
   заданное положение, пока не нажата «Вернуть автоматике» (D-034). После возврата
   реле сразу решает по последней цене и прогнозу.
   Панель «Принудительное включение» показывает состояние и режим реле.
   «Включить на N ч» включает реле сразу на N часов, не глядя на цену, аварийный
   предел, отпуск и интернет; во время работы кнопка называется «Перезапустить на N ч»
   и отсчитывает N часов заново. «Остановить» возвращает реле к автоматике. Оставшееся
   время видно на панели и оранжевой полосой на графике. N задается полем
   «Длительность, часов» в настройках реле. После перезапуска устройства включение
   не возобновляется. В ручном режиме кнопка «Включить на N ч» неактивна.
   Правила — [SCENARIOS.md](SCENARIOS.md) §6, §7.
3. «Вчера»/«Сегодня»/«Завтра» переключают сутки на графике без перезагрузки страницы.
   Серым закрашен план автоматики по 15-минутным интервалам; ручной режим на графике
   не показывается. Наведение мыши или касание показывает интервал, цену и причину.
   График рисует браузер, нужен включенный JavaScript.
   «Вчера» — план по текущим настройкам, фактическая работа — в истории (§7.1).
4. Измените параметры сценариев и нажмите «Сохранить настройки». Решение для
   реле пересчитается сразу (если не идет ручной режим или принудительное включение).
5. «Сохранить и перезапустить» — то же, плюс перезагрузка устройства. Идущее
   принудительное включение при этом заканчивается. Для смены сети Wi-Fi перезагрузка
   не нужна (§5).
6. Панель «Прошивка» внизу страницы — версия и обновление с GitHub (§7.2).

### 7.1 История переключений

Ссылка «История переключений» вверху страницы (`/history`). Таблица, новые события
сверху: время по Риге, реле, ВКЛ/ВЫКЛ и причина — сценарий, «Аварийный предел цены»,
«Нет актуальной цены больше часа», «Ручной режим», «Принудительное включение»,
«Ни один сценарий не выбрал интервал».
Строка «Запуск устройства» отмечает перезагрузку.

История хранится в оперативной памяти: последние 512 событий, до перезапуска или
пропадания питания. По ней удобно проверять, выполнялись ли условия сценариев.

При ошибке ввода возвращается страница с кодом 400 и короткой причиной
(например, `Invalid scenario settings`). Вернитесь назад и исправьте значения.

> Страница не защищена паролем. Любой, кто в той же сети, может менять настройки
> (KI-007). Не открывайте порт 80 в интернет.

### 7.2 Обновление прошивки

Панель «Прошивка» показывает установленную версию, статус и время последней проверки
(D-038).

- «Проверить обновление» спрашивает у GitHub последний релиз. То же устройство делает
  само: через 2 минуты после первой связи, затем раз в сутки. Автоматическая
  проверка только показывает «доступна новая версия X», ничего не ставит.
- «Обновить до X» загружает образ на QSPI-flash (около 2,5 минуты по Wi-Fi; реле,
  сценарии и страница работают как обычно), проверяет его (размер, начало файла,
  SHA-256), читает записанный файл обратно и сверяет еще раз, затем перезагружает
  устройство. Загрузчик переписывает прошивку — до 30 секунд реле
  выключены, светодиоды загрузчика мигают, страница недоступна. Затем устройство
  стартует с новой версией, как после обычного включения: настройки и Wi-Fi
  сохраняются, история переключений (RAM) начинается заново.
- Кнопка неактивна, пока на любом реле идет принудительное включение или включен
  ручной режим: перезагрузка сбросила бы их. Если включить одно из них во время
  загрузки, установка отменяется (образ остается на QSPI без флага, загрузчик его
  не трогает).
- Пока идет проверка или загрузка, страница обновляется сама раз в 5 секунд
  (несохраненные правки формы настроек при этом теряются).
- Ошибка загрузки (нет связи, ответ GitHub, контрольная сумма) не трогает установленную
  версию: причина — на панели и в логе `[FIRMWARE]`, повторить — той же кнопкой.
- Отката нет: если новая версия не запускается (нет `[FIRMWARE] Версия …` в логе
  запуска, страница не открывается), прошейте нужную версию по USB
  (`pio run -e opta -t upload` на ее коммите или `firmware.bin` из релиза).
- Нужен загрузчик версии 22 или новее (строка `[FIRMWARE] Версия X, загрузчик N` при
  запуске; та же версия — в режиме DFU, `dfu-util -l`, строка `@Bootloader version N`;
  «загрузчик 0» — версия не найдена, установка по сети запрещена) и стандартная разметка QSPI с разделом OTA (у Opta с завода). Если раздела
  нет, панель покажет «не удалось записать образ на QSPI-flash» — тогда разметка
  примером `QSPIFormat` из ядра (он стирает прошивку, после него — снова прошивка по
  USB; раздел 1 с прошивкой Wi-Fi пример сохраняет по запросу).

### 7.3 Восстановление, если устройство не запускается

Признак: после перезагрузки нет ни USB-порта, ни страницы, ни Wi-Fi. Загрузчик Arduino
во внутренней flash обновлением не затрагивается, поэтому прошивку можно вернуть по USB.

1. Закрыть Serial-монитор. Дважды быстро нажать RESET (утопленная кнопка у USB-C) —
   загрузчик остается в режиме DFU: в системе устройство `2341:0364`, в `dfu-util -l`
   три области — `@Internal Flash` (alt 0), `@External Flash` (QSPI, alt 1),
   `@Bootloader version N` (alt 2).
   Если плата работает, но видна как `FFFF:0264` или `FFFF:FFFF` на другом COM-порту
   (KI-032; прошивка обычно сама перезагружается из этого состояния), DFU не нужен:
   снять питание на 10 с или `pio run -e opta -t upload --upload-port COMn`.
2. Записать рабочий образ напрямую (PlatformIO перед загрузкой трогает COM-порт
   загрузчика и падает с «A device attached to the system is not functioning»):
   `dfu-util --device 0x2341:0x0364 -a 0 --dfuse-address=0x08040000:leave -D firmware.bin`
   (`dfu-util` — в `~/.platformio/packages/tool-dfuutil*/`; образ — `firmware.bin`
   релиза или `.pio/build/opta/firmware.bin`).
3. После `leave` устройство должно появиться как `2341:0264` за несколько секунд.

Через DFU можно и только читать: `-U файл` с `--dfuse-address=АДРЕС:ДЛИНА` — так
2026-10-26 проверялись образ приложения (`0x08040000`) и раздел OTA на QSPI
(`0x90100000`; в MBR разметки QSPI единица LBA — 4 КБ). Писать в QSPI (alt 1) — только
в раздел 2, раздел 1 — прошивка модуля Wi-Fi и сертификаты.

## 7a. Home Assistant (D-042, D-043)

1. Задайте брокер на странице (панель «Home Assistant (MQTT)») или командой `mqtt`.
   В логе: `[MQTT] Подключено за … мс, устройство opta_…`, затем
   `[MQTT] Описания для Home Assistant опубликованы: 21.`
2. В Home Assistant: Настройки → Устройства и службы → MQTT → устройство **Opta**.
   На каждое реле: «выход», «режим» (Авто / Вкл / Выкл), «причина», кнопки
   «принудительно включить» и «остановить принудительное»; общая сущность «Цена».
3. Режим «Вкл»/«Выкл» — ручной режим (держится до «Авто»), «Авто» — возврат автоматике
   (останавливает и принудительное включение). Команды пишутся в лог строками `[MQTT]`
   и `[MANUAL]`/`[FORCE]`.
4. Пока Home Assistant подключен, страница только для просмотра (§7). Пропал брокер —
   реле работают по расписанию, страница снова полная, плата переподключается сама
   (попытка раз в 10 с).

## 8. Serial-консоль

Монитор порта 115200 бод, команды завершаются переводом строки, регистр не важен.
Номер реле необязателен: без него используется последнее названное в консоли
(после запуска — реле 1). Выбор консоли и веб-страницы не связаны.

| Команда | Действие |
|---|---|
| `status [N]`, `?`, `info`, пустая строка | полный отчет; `N` выбирает реле для подробностей |
| `update`, `price` | без связи — только сообщение `[CMD] Нет связи с интернетом…`; иначе немедленный запрос цены в фоне; пересчет реле — когда придет цена, и еще раз по новому прогнозу. Если запрос уже идет, второй не ставится (`[TASK] Запрос цены уже идет…`). Если цена текущего интервала уже есть и API вернул ее же — `[TASK] Цена не изменилась…`, повторов раз в 30 с нет |
| `on N` / `off N` | ручное включение/выключение реле N — рычаг, до `auto N` (D-034); отменяет принудительное включение |
| `auto N` | вернуть реле N автоматике (в том числе остановить принудительное включение): решение сразу по последней цене и прогнозу, без запроса в сеть |
| `force N` | принудительное включение реле N на его `force_hours` часов; повтор — отсчет заново. В ручном режиме отклоняется |
| `force off N` | остановить принудительное включение реле N, вернуть автоматике |
| `history` / `history N` | последние 50 переключений всех реле / только реле N |
| `config reset` | только после ошибки чтения настроек при запуске (D-037): записать текущие настройки (значения по умолчанию) поверх нечитаемых и снова разрешить сохранение. Сохраненные настройки при этом теряются |
| `firmware` | версия прошивки, загрузчик, статус обновления (D-038) |
| `firmware check` | проверить новую версию на GitHub; итог — строкой `[FIRMWARE]` |
| `firmware install` | загрузить и установить новую версию (после `firmware check`); отклоняется при принудительном включении или ручном режиме. Устройство перезагрузится само |
| `mqtt` | брокер MQTT для Home Assistant и состояние соединения (D-042; только в прошивке с MQTT) |
| `mqtt <адрес> <пользователь> <пароль> [порт]` | задать брокер (порт по умолчанию 1883): сохраняется во flash, подключение сразу; регистр сохраняется |
| `mqtt off` | выключить MQTT (адрес стирается, пользователь и пароль остаются) |
| `sockets` | диагностика сети (D-031): кто из прошивки постоянно занимает сокеты и сколько свободно из 4 в ядре mbed. Ожидается (D-033): заняты 2 (HTTP-сервер, mDNS), свободны 2 — и на Wi-Fi, и с Ethernet; в точке настройки еще DNS. Свободные считаются открытием временных UDP-сокетов, они сразу закрываются. Во время запроса цены и подключения Wi-Fi не выполняется — повторить через минуту. Реле не трогает |

Каждые 10 секунд печатается короткая строка `[STATUS]`: состояние реле, цена, Wi-Fi.
Реле с принудительным включением помечены `принуд.`; в отчете `status` рядом с ним —
оставшееся время.

### Префиксы сообщений в логе

| Префикс | Источник |
|---|---|
| `[CONFIG]` | загрузка и миграция настроек |
| `[Ethernet]`, `[WiFi]` | сеть, точка доступа |
| `[WEB]` | HTTP-сервер настроек |
| `[mDNS]` | ответы на `opta-settings.local` |
| `[NTP]` | синхронизация времени |
| `[TASK]` | начало запроса цены, повтор через 30 с |
| `[HTTP]`, `[NORDPOOL-LV]` | запрос текущей цены |
| `[FORECAST]` | запрос прогноза цен |
| `[SCHEDULE]` | границы 15 минут, переключения по расписанию |
| `[DECISION]` | какой сценарий определил решение; строка `реле N ВКЛЮЧАЕТСЯ: <причина>`. При новой цене — всегда, при пересчете раз в минуту — только если строки плана изменились |
| `[RELAY]` | фактическое переключение реле |
| `[HOLIDAY]` | завершение отпуска: `Реле N: дата возвращения наступила…` |
| `[HISTORY]` | вывод команды `history` |
| `[FAILSAFE]` | аварийное выключение без цены |
| `[FORCE]` | принудительное включение: запуск, остановка, окончание, возврат к автоматике |
| `[BUTTON]`, `[CMD]` | ручное управление |
| `[BOOT]` | запуск после перезагрузки ради данных платы из QSPI (KI-032) |
| `[WATCHDOG]` | запуск watchdog |
| `[FIRMWARE]` | версия при запуске, проверка и загрузка обновления (D-038) |
| `[WARN]`, `[ERROR]` | предупреждения и ошибки |
| `[LOG]` | строки сетевого потока потеряны: буфер переполнился, пока `loop()` был занят |

Строки `[HTTP]`, `[FORECAST] Получено…`, `[NTP]`, `[FIRMWARE]` о запросах к GitHub и
ошибки запросов пишет фоновый поток.
Они печатаются основным потоком целыми строками, поэтому могут появиться в логе чуть
позже соседних строк, но всегда до реакции на результат запроса.

## 9. Диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Сразу после прошивки устройство в точке настройки, сохранение не помогает | KI-001, первая загрузка после прошивки; с D-029 перед точкой настройки 5 попыток за ~2–3 минуты | перезагрузить кнопкой RESET или по питанию; сохранить лог Serial первой загрузки (строки `[WiFi] Попытка N из 5…`) для разбора |
| После запуска 2–3 минуты нет ни Wi-Fi, ни точки настройки | сохраненная сеть недоступна: идут 5 попыток подключения (D-029) | подождать или удержать USER 5 секунд — точка настройки откроется сразу |
| Поля Wi-Fi на странице по Ethernet | Wi-Fi не подключился, работа идет по Ethernet | ввести SSID и пароль, чтобы сменить сеть, или оставить пустыми |
| `opta-settings.local` не открывается (`DNS_PROBE_FINISHED_NXDOMAIN`) | клиент не поддерживает mDNS (старые Android, Windows без Bonjour, включен «Частный DNS» или VPN на телефоне) либо прошивка до исправления KI-033 — в логе `[mDNS] Ответ … отправлен`, а имя не находится | открыть по IP из лога или `[STATUS]`; на Android — выключить «Частный DNS»/VPN |
| Реле выключились, в логе `[FAILSAFE]` | больше часа нет новой цены: нет интернета или Elering недоступен | проверить Wi-Fi и доступ к `dashboard.elering.ee`; после восстановления реле вернутся сами |
| `[WARN] API пока возвращает устаревшую цену` | Elering еще не опубликовал цену нового интервала | норма в первые минуты интервала, повтор через 30 с |
| `[NTP] Сервер времени не ответил` | UDP 123 заблокирован или нет интернета | повтор раз в 60 с; без времени решения не принимаются |
| Реле не реагирует на цену и сценарии | реле в ручном режиме (рычаг, D-034): режим «Ручной» на странице и в `status` | «Вернуть автоматике» на странице или `auto N` |
| Ночью реле не включилось или проработало меньше N часов | ночью был сбой: перезагрузка, пропадание питания, нет интернета или цен; прошедшие выбранные интервалы засчитываются (D-012) | проверить историю переключений и лог; ожидаемо по решению D-012 |
| `[WARN] … ждет цен` | прогноз еще не покрывает окно сценария: цены на завтра публикуются около 14:00 | норма до публикации; если держится вечером — проверить доступ к Elering |
| Реле включено, хотя цена выше порога включения | включил другой сценарий: «Умный порог включения» (N самых дешевых интервалов суток, цена не важна), «Включение ночью» (сдвиг к концу окна до +1 ц, D-016) или пробуждение; либо цена нового интервала еще не пришла (первые минуты после :00/:15/:30/:45 решение действует по прежней цене) | навести на интервал графика — подсказка пишет причину; страница `/history` — причину каждого переключения |
| На графике «Цен на эти сутки пока нет» на вкладке «Сегодня» | прогноз еще не получен | с D-028 запрос повторяется раз в минуту сам; в логе `[FORECAST] Прогноз не покрывает текущее время…`; если держится — смотреть `[ERROR]` рядом |
| Реле часто включается и выключается | выбор идет 15-минутными интервалами, не обязательно подряд (D-014) | ожидаемо; минимальное время работы появится с конфигом v6 |
| «Вчера» на графике не совпадает с историей | вчерашний план пересчитан по текущим настройкам | смотреть историю переключений |
| `[WARN] …: нужно 15-минутных интервалов X, в окне доступно Y` | задано больше часов, чем есть в окне (ночь перехода на летнее время, отпуск > 10 ч) | ожидаемо; работают все интервалы окна |
| Принудительное включение закончилось, а реле выключилось, хотя сценарий должен был включить | нет актуальной цены (failsafe) или цена еще не приходила: без цены автоматика выключает реле | проверить интернет и лог `[FORCE]`, `[FAILSAFE]` |
| Устройство само перезагрузилось | сработал watchdog: где-то завис цикл | прислать лог Serial до перезагрузки |
| Мигает красный светодиод, USB-порта нет | фатальная ошибка mbed (остановка с миганием); с D-041 watchdog перезагружает устройство через ~33 с | подождать минуту; если мигание повторяется после каждой перезагрузки — снять питание на 10 с, затем прошивка по USB (§7.3) |
| `[ERROR] Сетевой запрос не завершился за 180 с; перезагрузка устройства.` | поток запросов завис в DNS или TLS (D-026); до исправления KI-031 — иногда ложно, сразу после начала запроса | если повторяется — прислать лог Serial перед этой строкой |
| «Проверка не удалась: не удалось соединиться с GitHub» | все 3 попытки TLS не прошли: нет доступа к `github.com:443`, все сокеты заняты соединениями браузера (KI-028) или TLS не прошел (сертификаты модуля Wi-Fi) | закрыть лишние вкладки страницы и повторить; если держится — прислать лог `[FIRMWARE]` |
| `[FIRMWARE] Не удалось установить TLS-соединение с … (попытка N из 3)` | соединение не открылось, загрузчик повторит через 4 с (KI-028) | ничего, если следующая попытка прошла |
| `[FIRMWARE] UPDATE.BIN на QSPI не совпал с образом…` или `Ошибка записи на QSPI (код)` | записанный файл не читается как скачанный: сбой QSPI-flash или ее состояние после перезагрузки посреди записи (KI-032) | снять питание на 10 с (или прошить текущую версию по USB) и повторить «Обновить» |
| `[BOOT] Данные платы из QSPI не прочитались при прошлом запуске…` | прошлый запуск пришелся на незаконченное стирание или запись QSPI (перезагрузка во время загрузки обновления), устройство перезагрузилось само (KI-032) | ничего; если загрузка обновления оборвалась — повторить «Обновить» |
| `[ERROR] Данные платы из QSPI не прочитаны и после перезагрузки…` | микросхема QSPI не отвечает на чтение служебной области (KI-032): плата видна как VID 0xFFFF, обновление по сети и TLS могут не работать | снять питание на 10 с; если повторяется — прислать лог |
| «Обновить» неактивна при доступной версии | идет принудительное включение или ручной режим (D-038) | дождаться конца или остановить, вернуть реле автоматике |
| После «Обновить» устройство не вернулось | новая версия не стартует или загрузчик не поставил ее | подождать 2 минуты; затем прошивка по USB (§7.2) и лог Serial первой загрузки |
| `[WARN] Сетевой запрос не завершился за 180 с; перезагрузка отложена до конца принудительного включения.` | то же, но идет принудительное включение (D-026, п. 6) | ждать: после конца включения устройство перезагрузится само; можно остановить включение, тогда сразу |

## 10. Сброс

- **Wi-Fi:** удержать USER 5 секунд и ввести новую сеть.
- **Настройки реле:** отдельной команды сброса нет. Можно задать значения на странице
  вручную (значения по умолчанию — [SCENARIOS.md](SCENARIOS.md) §3) или стереть flash
  при прошивке.
