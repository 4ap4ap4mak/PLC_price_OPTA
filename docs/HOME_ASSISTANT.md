# Интеграция с Home Assistant

План и правила интеграции Opta с Home Assistant (HA) через MQTT. Решение — D-042.
Статус: **прототип проверен на железе, настоящая реализация не начата** (§7).

## 1. Принцип: решает Opta, HA — пульт и экран

- Цену (Elering), план, сценарии, failsafe, ручной режим и принудительное включение
  по-прежнему ведет `Controller` на Opta. HA реле напрямую не переключает.
- HA показывает все: цену, прогноз и план (график), состояние и причину по каждому
  каналу, историю, диагностику. HA меняет все настройки и подает те же команды, что
  страница, консоль и кнопка USER.
- Если HA, брокер, ПК с брокером или Wi-Fi пропали, реле работают по последним
  настройкам — как сейчас без сети (D-035). Безопасность реле не зависит от HA.
- Режим «внешнее управление» (HA командует каналом напрямую с таймаутом и возвратом
  к автоматике) отложен до отдельного решения пользователя.

```
 Opta ──цена, состояние, описания сущностей──▶ Mosquitto (порт 1883) ──▶ Home Assistant
 Opta ◀──────────── команды и настройки ────── Mosquitto              ◀── пользователь в HA
```

Брокер — Mosquitto: дополнение HA (HAOS) или отдельный контейнер. Связь только
в домашней сети, интернет для нее не нужен.

## 2. Что установить

| Что | Зачем |
|---|---|
| Home Assistant (HAOS на Raspberry Pi / мини-ПК, или Docker на ПК для проверки) | пульт и экран |
| Брокер Mosquitto | обмен сообщениями Opta ↔ HA |
| Пользователи брокера: отдельный для Opta и для HA | вход без пароля на брокере запрещен |
| Интеграция MQTT в HA | HA подписывается на брокер и сам создает сущности (MQTT Discovery) |
| HACS + карточка `apexcharts-card` | график цены и плана в HA (шаг 9) |
| MQTT Explorer на ПК | отладка: все топики и ручная отправка команд |
| Постоянный IP компьютера с брокером (резерв DHCP в роутере) | Opta подключается к брокеру по IP: mDNS-имена (`homeassistant.local`) ядро mbed не разрешает |

Если брокер на Windows: входящие на TCP 1883 из локальной сети должны быть разрешены
брандмауэром (в профиле сети «Общедоступная» по умолчанию закрыты).

Пароли брокера в репозиторий не попадают (репозиторий публичный, D-038).

## 3. Поведение устройства (D-042)

| Что | Поведение |
|---|---|
| Сайт, пока HA подключен (MQTT-соединение открыто) | **только просмотр**: состояние, график, история; формы настроек, панели ручного режима, принудительного включения и прошивки недоступны, на странице — плашка «Управляется из Home Assistant» |
| Сайт без HA | как сейчас, полностью |
| Ручное управление из HA | на каждый канал выбор «Авто / Вкл / Выкл»; «Вкл»/«Выкл» — ручной рычаг D-034 (держится до «Авто»); состояние выхода и причина — отдельными сущностями |
| Кнопка USER | без изменений: короткое нажатие — рычаг реле 1 (аварийное вкл/выкл без сети и без HA), удержание 5 с — точка настройки |
| Serial-консоль | без изменений, сервисный доступ по USB; добавится команда `mqtt` |
| Адрес брокера, порт, пользователь, пароль | страница точки настройки (удержание USER 5 с), страница без HA и команда `mqtt`; хранятся во flash отдельным ключом — формат `device_config` (v5) не меняется |
| Сохранение настроек из HA во flash | через ~10 с после последнего изменения и только если значение изменилось; новое значение действует сразу, задержка касается только записи (износ flash) |
| Доступность | сообщение `online` при подключении, `offline` — завещанием брокеру: HA показывает «Недоступно», если плата пропала |

## 4. Сущности в HA (план)

Описания публикуются одним сообщением device discovery
(`homeassistant/device/<id>/config`), `<id>` — из MAC платы.

**Устройство:** текущая цена; прогноз и план (атрибуты для графика); цена актуальна /
failsafe; кнопка «Обновить цену»; сущность `update` для прошивки (установленная
и последняя версия, кнопка «Установить» — те же ограничения, что на странице, D-038);
диагностика: RSSI, IP, время работы, канал связи.

**Каждый канал (`kChannelCount`):** выход вкл/выкл; режим «Авто / Вкл / Выкл»; причина;
следующее переключение; кнопки «Принудительно на N ч» и «Стоп»; длительность
принудительного включения; аварийный предел; порог включения; переключатели
и параметры сценариев (ночь, умный порог, пробуждение, отпуск). Время — текстом
`ЧЧ:ММ`, дата отпуска — `ГГГГ-ММ-ДД` (в MQTT-интеграции HA нет сущностей time/date).

Имена сущностей нейтральные (D-010): «канал», «выход», «включено».

## 5. Ресурсы и ограничения

**Сокеты (D-031).** Лимит ядра — 4 на все устройство. Замер прототипа 2026-10-27
(Wi-Fi): HTTP-сервер + mDNS + MQTT заняты, свободен 1. Через него идут по очереди запрос
цены, NTP и прошивка (один поток `FetchWorker`) и посетитель страницы. Совпадение
запроса цены с открытием страницы — страница не отвечает пару секунд и открывается
повторно, цена приходит (проверено). Сайт в режиме просмотра остается, поэтому это
поведение сохраняется.

**Потоки.** MQTT — отдельный поток, как `FetchWorker` и `WifiConnector`: подключение
к брокеру блокирует, `loop()` его не ждет. С основным потоком — очереди под мьютексом;
`Controller` трогает только основной поток. Пока `WifiConnector` подключается
(uplink `None`), поток MQTT сеть не трогает.

**Память.** Прототип добавил ~7 КБ flash: 559 КБ из 768 КБ (сборка 1.0.3 — 552 КБ),
RAM 26 %. Описания сущностей — строки в flash, полный набор — оценка 10–20 КБ. Если
станет тесно — разбивка flash `75_25` (1,25 МБ прошивке, ядро M4 не используется), но
сначала проверить ее с обновлением по сети.

**Без TLS.** MQTT в домашней сети без шифрования: второй TLS-клиент не помещается по
памяти и сокетам. Защита — логин и пароль брокера.

## 6. Как проверять

1. **Тесты на ПК (`env:native`)**: описания сущностей и топики, разбор команд
   (значение вне диапазона отвергается, неверное время/дата не применяются), задержка
   сохранения.
2. **Стенд без HA**: Opta + брокер + MQTT Explorer — описания, `online`/`offline`,
   команды вручную, строки `[MQTT]` в Serial, `sockets`.
3. **С HA**: устройство появилось со всеми сущностями; каждую настройку изменить в HA →
   проверить в Serial и на странице; перезагрузка Opta — настройки на месте;
   перезапуск HA — сущности восстанавливаются сами.
4. **Отказы**: остановить брокер — реле работают по плану, сайт снова полный; вернуть —
   плата переподключается сама; потеря Wi-Fi; неверный пароль брокера; пропажа
   цены — failsafe как раньше.
5. **Длительный прогон 1–3 суток**: нет перезагрузок watchdog, число переподключений
   разумное, `sockets` стабильно.
6. **Прошивка из HA**: «Установить» → плата обновилась и вернулась с новой версией.

Только проверки, восстановимые по USB (без прерывания записи во flash).
