# Известные проблемы и ограничения

Номера `KI-NNN` постоянные: на них ссылаются другие документы и коммиты. Исправленный
пункт не удаляется, а переносится в раздел «Исправлено» с указанием коммита.

Важность: **высокая** — может оставить реле в неверном состоянии или сделать устройство
недоступным; **средняя** — неверное, но безопасное поведение; **низкая** — неудобство.

## Открытые

### KI-028. Проверка обновления с кнопки не соединялась с GitHub — средняя (исправление ждет проверки)

- **Откуда:** на железе 2026-10-25, версия 1.0.0: кнопка «Проверить» → `[FIRMWARE] Не
  удалось установить TLS-соединение с github.com`. Автоматическая проверка после
  запуска (без открытой страницы) с той же сетью проходила.
- **Причина (по коду и логу):** в ядре mbed 4 сокета на все устройство, 2 постоянно
  у HTTP-сервера и mDNS (KI-017). Сразу после `POST /firmware` браузер открывает страницу
  заново (`GET /?relay=N`) и держит запасное соединение (в логе — «Запрос отклонен:
  таймаут»): сокета для DNS и TLS к GitHub в этот момент нет.
- **Исправление (ветка `feature/ota-update`):** до 3 попыток TLS-соединения с паузой
  4 с, в лог — номер неудачной попытки. Соединения браузера живут секунды.
- **Проверить:** «Проверить» на странице → `Последний релиз: …` (допустимы строки
  «попытка 1 из 3»).

### KI-017. Ethernet после Wi-Fi может занять все сокеты — высокая (исправление ждет проверки с Ethernet)

- **Откуда:** разбор кода (D-031), на устройстве не воспроизводилось. В ядре mbed Opta
  на все устройство 4 сокета (`MBED_CONF_LWIP_SOCKET_MAX = 4` в `mbed_config.h`, ядро
  собрано заранее, настройкой не меняется). До D-032/D-033 на Wi-Fi постоянно были
  заняты три: HTTP-сервер, mDNS и UDP-сокет NTP; запросу цены доставался четвертый.
- **Сейчас (D-033):** постоянно заняты 2 сокета при любом сочетании интерфейсов (в точке
  настройки — 3 с DNS); пункты ниже — история разбора.
- **Бюджет подтвержден на железе** (2026-10-22, команда `sockets`, работа на Wi-Fi без
  Ethernet): заняты HTTP-сервер Wi-Fi, mDNS Wi-Fi и NTP, свободен 1, лимит 4.
  Не проверен только сам сценарий с кабелем.
- **Сценарий:** Wi-Fi подключился раньше, чем Ethernet получил адрес (DHCP дольше 3 с
  после запуска или кабель вставлен во время работы). `serviceWiredNetwork()` поднимает
  HTTP-сервер и mDNS на Ethernet, а серверы Wi-Fi не останавливаются: 5 сокетов из 4.
  Ожидаемо: запуск mDNS или сервера Ethernet не удается, а если удается — запросу цены
  не хватает сокета, цены не приходят, через час failsafe выключает реле.
- **Как проверить:** команда `sockets` (число свободных сокетов) до и после того, как
  вставить кабель при работе на Wi-Fi, и лог ближайшей границы 15 минут.
  Сейчас у пользователя нет доступа к кабелю.
- **Частично смягчено (D-032, ветка `feature/wifi-reconnect`):** сокет NTP закрывается
  после каждого запроса — на Wi-Fi постоянно заняты 2, свободны 2. В сценарии с кабелем
  постоянных нужно 4 (по 2 на интерфейс), и запросу цены все равно не хватит.
- **Исправление (D-033, в `main`), ждет проверки на железе:**
  один HTTP-сервер и один mDNS на все интерфейсы — постоянно 2 сокета при любом
  сочетании Wi-Fi и Ethernet. Без кабеля проверяется, что страница и mDNS работают по
  Wi-Fi и в точке настройки; с кабелем — `sockets` до и после подключения кабеля и
  цена на ближайшей границе 15 минут.

### KI-007. Веб-интерфейс без защиты — средняя

- Нет пароля и защиты от CSRF: любой в локальной сети, а также вредоносная страница
  в браузере пользователя могут менять настройки и Wi-Fi.
- Пароль точки доступа `opta1234` одинаков для всех устройств и зашит в коде.
- Пароль Wi-Fi хранится во flash открытым текстом.
- С D-038 любой в сети может также запустить установку последнего релиза с GitHub
  (только официального: образ берется из репозитория и проверяется по SHA-256).
- **Исправление:** шаг 2h+ (авторизация/CSRF).

### KI-008. Интернет только через Wi-Fi — низкая (исправление ждет проверки с Ethernet)

Ethernet использовался только для страницы настроек, цены и NTP по проводу не работали.
**Исправление (D-036, в `main`):** без Wi-Fi цены и NTP идут
через Ethernet, маршрут по умолчанию стека выставляется перед каждым запросом. Не
проверено на железе: нужен кабель — запуск без Wi-Fi (или с неверным паролем), в логе
`[HTTP] Подключение к … через Ethernet...`, цена и график.

### KI-009. При работающем Ethernet страница была недоступна по Wi-Fi — низкая (исправление ждет проверки с Ethernet)

- **Было:** при запущенном HTTP-сервере на Ethernet сервер и mDNS на Wi-Fi не
  стартовали: два сервера с mDNS заняли бы все 4 сокета ядра mbed (D-031, KI-017).
- **Сейчас (D-033, в `main`):** один сервер и один mDNS на все интерфейсы — страница
  по IP Wi-Fi работает и при Ethernet; `opta-settings.local` отвечает адресом Ethernet
  (если кабель и Wi-Fi в разных сетях, из Wi-Fi — только по IP).
- **Проверить с кабелем:** страница по IP Wi-Fi при подключенном Ethernet.

## Ограничения по замыслу

- Веб-сервер обслуживает одно соединение за раз (бывший KI-016, D-031). Остальные ждут
  в очереди, пока есть свободный сокет (4 на все устройство, ядро mbed); если сокета нет,
  подключение сразу сбрасывается — помогает обновить страницу. С D-032 на Wi-Fi свободны
  2 сокета: посетитель помещается и во время запроса цены, третий одновременный — нет. Страница — один запрос: график встроен (D-020), иконка пустая.
- Запуск и остановка точки настройки (`WiFi.beginAP`, `WiFi.disconnect`) идут
  в основном потоке и на это время останавливают `loop()` (остаток KI-006, D-031).
  Бывает редко: после неудачных попыток подключения или по кнопке USER.
- Ручной режим — рычаг: действует, пока реле не вернут автоматике, и снимается только перезагрузкой ([SCENARIOS.md](SCENARIOS.md) §7, D-034).
- Обновление по сети без отката и без подписи образа (D-038): если новая версия не
  стартует — прошивка по USB. Во время установки (до ~30 с) реле выключены.
  Установка недоступна при принудительном включении и в ручном режиме.
- Только зона цен LV и часовой пояс Europe/Riga.
- Кнопка USER управляет только реле 1.
- Принудительное включение не восстанавливается после перезагрузки (D-007).
- Принудительное включение перекрывает аварийный предел, отпуск и failsafe; ограничено
  только своим таймером, не больше 24 часов (D-007).
- При сбое (перезагрузка, пропадание питания, поздний прогноз) выбор интервалов идет
  по всему окну, и прошедшие выбранные интервалы считаются отработанными: возможен
  недобор часов за окно (D-012). Пропущенные из-за failsafe, аварийного предела или
  ручного режима интервалы не добираются.
- Ночное окно, которое начинается раньше публикации цен на завтра (~14:00) и уходит за
  полночь, может отработать меньше N часов: интервалы, прошедшие до публикации,
  засчитываются (D-012). Окна 23:00–07:00 и другие, начинающиеся после 14:00, это не касается.
- Окно отпуска — 10 часов перед возвращением; `holiday_hours` больше 10 работает как
  «все интервалы окна» (D-015).
- Реле может переключаться каждые 15 минут: минимального времени работы нет (D-014).
- История переключений живет в RAM, 512 событий, и пропадает при перезапуске (D-019).
- График «Вчера» показывает план по текущим настройкам, а не фактическую работу (D-018).
