# Внешние интерфейсы

Всё, с чем прошивка обменивается данными: API, протоколы, форматы хранения.
Значения взяты из кода `src/net/`, `src/web/` и `lib/`. При изменении кода обновлять этот файл.

## 1. API Elering (цены Nord Pool)

Хост `dashboard.elering.ee`, порт 443, HTTPS (`WiFiSSLClient`), запросы HTTP/1.0
с `Connection: close`, заголовки `User-Agent: ArduinoOpta-PLC/1.0`,
`Accept: application/json`. С шага 2g запросы выполняет фоновый поток `FetchWorker`
(`src/net/`), по одному за раз; чтение ответа — до 20 с, без байтов — до 5 с.

### 1.1 Текущая цена

```
GET /api/nps/price/lv/current
```

Ответ (используемые поля):

```json
{ "success": true, "data": [ { "timestamp": 1760950800, "price": 85.12 } ] }
```

- `timestamp` — начало 15-минутного интервала, Unix epoch UTC, секунды.
- `price` — **EUR/MWh**, в прошивке делится на 1000 → EUR/kWh.
- Лимит тела ответа: 4096 байт. Правила проверки — [SCENARIOS.md](SCENARIOS.md) §5.

### 1.2 Прогноз

```
GET /api/nps/price?start=2026-10-19T21:00:00.000Z&end=2026-10-21T20:45:00.000Z
```

- `start` — местная полночь сегодня (Europe/Riga) в UTC; `end` — завтра 23:45 местного.
- Ответ: `{ "success": true, "data": { "ee": [...], "fi": [...], "lv": [ { "timestamp": ...,
  "price": ... }, ... ], "lt": [...] } }`. Разбирается только `data.lv` (фильтр ArduinoJson).
  Тело за двое суток — около 32 КБ, лимит — 40 000 байт.
- Запрашивается после каждой новой цены (раз в 15 минут). Сохранение настроек прогноз
  не запрашивает: решение строится по уже загруженному (KI-011 исправлен).
- **Вчерашние цены** (D-018): при обновлении слоты прежнего ряда начиная со вчерашней
  местной полуночи сохраняются перед новым прогнозом. Если вчерашних цен нет (после
  запуска), тем же путем запрашиваются одни сутки: `start` — вчера 00:00, `end` — вчера
  23:45 местного (`elering::dayPricesPath`, ~16 КБ). Если не удалось — повтор при
  следующем обновлении прогноза.
- При неудачном запросе прежний ряд не стирается: новый ответ разбирается в отдельный
  буфер (D-018).
- Хранится до 300 слотов (`prices::kMaxSlots`): вчера, сегодня, завтра и запас на сутки
  в 25 часов. Слоты принимаются только строго по возрастанию времени.
- Разбор и проверки — `lib/elering` (`parseCurrent`, `parseForecast`, `forecastPath`,
  `dayPricesPath`), тесты на реальных ответах — `test/test_elering`.
- Цены на завтра появляются после результатов аукциона day-ahead Nord Pool (около
  13:00 CET, то есть ~14:00 по Риге; в Elering — с некоторой задержкой). До этого прогноз
  содержит только сегодняшний день.

## 2. Время

- NTP: `pool.ntp.org:123`, локальный UDP-порт 2390, ожидание ответа до 1,5 с.
  С шага 2g запрос (вместе с разрешением имени) выполняет фоновый поток `FetchWorker`,
  раньше запроса цены, если оба ждут очереди; время отсчитывается от момента ответа.
- Ответ отклоняется, если режим ≠ 4 (server), stratum = 0 или время раньше 2025-01-01.
- Повтор синхронизации: раз в 60 с, пока время не получено; затем раз в 6 часов.
- Между синхронизациями время считается как `epoch_sync + (millis() − millis_sync)/1000`.
- Часовой пояс зашит в коде: Europe/Riga, UTC+2 зимой и UTC+3 летом, переходы
  в последнее воскресенье марта и октября в 01:00 UTC.

## 3. HTTP-сервер настроек (порт 80)

Один сервер на все интерфейсы (D-033): сокет слушает порт 80 без привязки к адресу
в общем стеке ядра mbed и принимает подключения по Wi-Fi, точке настройки и Ethernet.
Открывается при первом адресе и дальше не перезапускается.

Один и тот же обработчик работает на Wi-Fi (STA или AP) и на Ethernet.

| Метод и путь | Назначение |
|---|---|
| `GET /` или любой неизвестный путь | страница настроек реле 1, график на сегодня |
| `GET /?relay=N&day=D` | страница реле N (1–4), начальная вкладка графика D (−1 — вчера, 0 — сегодня, 1 — завтра). Параметры действуют только на этот запрос: сервер не запоминает выбор, у каждой вкладки браузера свой (KI-010). Нет параметра или он неверный — реле 1 / сегодня |
| `GET /history?relay=N` | история переключений всех реле, новые сверху; ответ без `Content-Length`, конец — закрытие соединения. `relay` — куда ведет ссылка «Настройки» (`/?relay=N`, D-030); без параметра — реле 1 |
| `POST /save` | сохранить настройки (urlencoded-форма, ≤ 2048 байт); `503`, если запись заблокирована после ошибки чтения настроек при запуске (D-037) |
| `POST /manual` | ручной режим (рычаг, D-034): `relay=N&action=on` / `action=off` — включить/выключить реле N вручную до возврата автоматике, `action=auto` — вернуть автоматике (и остановить принудительное включение); необязательное `chart_day=D`; ответ `303` → `/?relay=N` (как у `/force`), `400` при неверном реле или действии |
| `POST /firmware` | обновление прошивки (D-038): `relay=N&action=check` — проверить новую версию на GitHub, `action=install` — загрузить и установить; необязательное `chart_day=D`; ответ `303` → `/?relay=N` (итог и отказ — на панели «Прошивка»), `400` при неверном реле или действии |
| `POST /force` | `relay=N&action=start` — принудительное включение реле N на `force_hours` (повтор — отсчет заново), `action=stop` — остановить и вернуть автоматике; необязательное `chart_day=D` — открытая вкладка графика; ответ `303` → `/?relay=N` (или `/?relay=N&day=D`, если вкладка не «Сегодня», D-030), `400` при неверном реле или действии |

Страница настроек содержит данные графика (`<script>var CHART={...}`): `n` — сейчас,
`d` — вкладка, `c` — текущая цена, `t0` + `t` — интервалы, `p` — цены в ц/кВт·ч,
`r` — бит 16 «план включает реле» + номер `planner::Reason`, `rn` — названия причин,
`ro` — номера причин, которые выключают реле (отпуск без интервала, аварийный предел),
`f` — конец принудительного включения выбранного реле, epoch UTC (0 — не идет).
Рисует браузер (D-020). Отдельного маршрута графика нет: сервер обслуживает одно
соединение за раз, второй параллельный запрос сбрасывается (KI-016). По той же
причине страницы объявляют пустую иконку (`<link rel='icon' href='data:,'>`).

Ответы `POST /save`: `303 See Other` → `/?relay=N` (реле из формы; с `&day=D`, если в форме
вкладка графика не «Сегодня», D-030) при успехе; `400` с текстом причины;
`408`, если тело пришло не полностью; `500` при ошибке записи во flash.
`action=save_restart` → перезагрузка через 0,5 с. Новые учетные данные Wi-Fi без
`save_restart` → `200` со страницей «Сеть Wi-Fi сохранена» (без перенаправления: точка
настройки сейчас закроется), через 1,5 с — подключение к новой сети без перезагрузки
(D-031).

Поля формы `/save`: `relay`, `safety`, `threshold`, `smart_enabled`, `smart_hours`,
`wakeup_enabled`, `wakeup_hours`, `wakeup_time`, `night_enabled`, `night_start`,
`night_end`, `night_hours`, `force_hours`, `holiday_enabled`,
`return_local`, `holiday_hours`, `action`, `chart_day` (вкладка графика −1/0/1 для
адреса возврата; нет или неверное — 0), а при видимых полях Wi-Fi — `manual_ssid`
(или `ssid`) и `password`. Флажки передают значение `1`. Поле `block_enabled` с шага 2c
не читается, а старое имя `block_hours` вместо `force_hours` дает ошибку 400.

Ограничения сервера: строка запроса и заголовка ≤ 512 байт, ≤ 32 заголовков,
общий таймаут чтения заголовков 3 с, тела — 5 с. Аутентификации нет (KI-007).

## 4. mDNS и DNS

- **mDNS:** ответ на A-запрос (или ANY) `opta-settings.local`, класс IN, TTL 120 с. В лог `[mDNS]` пишутся только отправленные ответы, чужие пакеты — нет (KI-026).
  Один ответчик на устройство (D-033): с адресом Ethernet, если он есть, иначе Wi-Fi
  или точки настройки; при смене адреса перезапускается (подписка на группу идет на
  поднятых в этот момент интерфейсах). Multicast 224.0.0.251:5353.
  Unicast-ответ — если запрос пришел не с порта 5353 или с битом QU.
- **Captive DNS** (только в режиме точки доступа): UDP 53, на запрос A или ANY любого
  имени отвечает A-записью 192.168.4.1, TTL 60 с; на AAAA и прочие типы — ответом без
  записей (NOERROR), чтобы клиент перешел к A-запросу (KI-024).

## 5. Хранение во flash (KVStore mbed)

| Ключ | Содержимое | Размер |
|---|---|---|
| `/kv/wifi` | `WifiCredentials { char ssid[33]; char password[64]; }`, пароль открытым текстом | 97 байт |
| `/kv/device_config` | массив `ChannelConfig[4]` (версия 5) | 4 × 36 = 144 байта |

Чтение и запись — `lib/configstore` (`ConfigStore`, `WifiCredentialStore`) через
`src/platform/KvStorage` (`kv_get_info`/`kv_get`/`kv_set`).

Формат `/kv/device_config` определяется **по размеру блоба**:

| Размер блоба | Формат | Действие |
|---|---|---|
| 32 (`LegacyChannelConfig`) | v2/v3, одно реле | импорт в реле 1; для v2 цены делятся на 1000 (были EUR/MWh) |
| 128 (`LegacyChannelConfig[4]`) | v4, 4 реле без умного порога и пробуждения | импорт всех 4 реле |
| 144 (`ChannelConfig[4]`) | v5, текущий | загрузка как есть |
| другой | неизвестный | настройки по умолчанию и перезапись |

Конфигурация реле, не прошедшая проверку, заменяется значениями по умолчанию.
Блоб — сырая структура C. **Любое изменение полей `ChannelConfig` меняет формат
во flash** и требует новой версии и миграции. Распознавание и миграция —
`channelconfig::decode`; смещение каждого поля зафиксировано тестом
`test_blob_layout_is_frozen` (`test/test_channelconfig`).

## 6. Обновление прошивки (GitHub Releases, D-038)

Источник — последний релиз публичного репозитория (не черновик и не pre-release),
TLS до порта 443, сертификат проверяет TLS-клиент ядра (`/wlan/cacert.pem`).
Запросы — `HTTP/1.0`, `User-Agent: ArduinoOpta-PLC/1.0`; перенаправления 301/302/303/
307/308 — до 5, только `https` и порт 443 (`Location` до ~1,5 КБ: подписанная ссылка
`release-assets.githubusercontent.com`).

| Запрос | Путь |
|---|---|
| Манифест последнего релиза | `https://github.com/4ap4ap4mak/PLC_price_OPTA/releases/latest/download/manifest.json` |
| Образ версии X.Y.Z | `https://github.com/4ap4ap4mak/PLC_price_OPTA/releases/download/vX.Y.Z/firmware.bin` |

Манифест (до 1 КБ):

```json
{"board":"opta","version":"1.0.1","size":547840,"sha256":"<64 hex>"}
```

`board` — строго `opta`; `version` — `X.Y.Z` без `v`; `size` — 64 КБ…768 КБ (окно
приложения `0x08040000…0x08100000`); `sha256` — от `firmware.bin`. 404 — релизов нет.

Образ пишется в файл `UPDATE.BIN` в FAT на разделе 2 MBR внешней QSPI-flash (раздел
OTA 5 МБ из стандартной разметки `QSPIFormat`; нет FAT — раздел форматируется,
раздел 1 с прошивкой Wi-Fi и сертификатами не трогается). Флаг загрузчику (версия 22+,
байт 1 по адресу `0x0801F000`) — регистры RTC backup перед перезагрузкой:

| Регистр | Значение |
|---|---|
| `DR0` | `0x07AA` — есть обновление |
| `DR1` | `0xA4` — QSPI, FAT, MBR |
| `DR2` | `2` — раздел |
| `DR3` | длина образа, байт |
